  - 3 個變體皆先讀過 `design-system.md` 已核准的 S3 token 與 S4 元件庫才動工，色彩/字級/間距/圓角/陰影/按鈕樣式與元件庫實際 CSS 數值一致（token 值直接從 `src/styles/tokens.css` 複製，非憑空捏造）。

  - 人工選定**變體 B（對頁書本跨頁）**，理由是最貼近「仿手繪素描日記本」的產品定位——打開頁面就像攤開一本真的筆記本。
  - 選定後歷經三輪修改，最終確認「可以，沒有問題」：
    - **第一輪**（4 項細節）：① 左頁動作按鈕改為「刪除」（靠左）＋「存檔／完成」（分組靠右）三顆；② 左頁底部新增「← 上一篇」頁角翻頁按鈕；③ AI 生成圖片區移除實心淺色背景框，改為虛線素描框（透明背景），符合「素描本不會特別把插圖上色框出來」的要求；④ 右頁底部只留「下一篇 →」，移除「共 X 篇．第 X 篇」頁碼文字。
    - **第二輪**（互動模型修正，使用者提供實體日記本參考圖後）：發現最初實作誤解為「左頁固定今天、右頁可獨立瀏覽任何日期」，實際應為**一個跨頁＝一個日期，左右頁同步隨「上一篇／下一篇」翻動**。今日未完成時右頁維持乾淨空白（僅淡化提示文字，無 placeholder 方框）；已完成日期左頁變唯讀、不提供任何編輯入口。另要求底部翻頁導覽永遠貼齊頁面最下緣（以 `panel-content { flex: 1 1 auto }` 撐開剩餘空間實作，並用「今日短文字」與「歷史短文字＋較高 AI 內容」兩種情境截圖驗證對齊），且今日／未完成狀態直接不渲染「下一篇」按鈕（非僅 disabled）。
    - **第三輪**（間距微調）：底部導覽列與上方內容間補回固定 `margin-top: 20px`，修正「今日文字較長時，動作按鈕看起來貼齊分隔線」的視覺問題。
  - 過程中發現元件庫缺少多行輸入元件（`Input` 只支援單行），依 `ui-mockup-gate.md` 規則新做 `Textarea`（沿用 `Input` 的邊框/圓角/focus/error/disabled 樣式與 token，新增字數統計顯示），並登記回 `design-system.md` 元件庫 inventory（來源階段標記為「S5 補做並回登」）。
