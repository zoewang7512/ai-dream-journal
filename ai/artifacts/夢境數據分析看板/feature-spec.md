# 功能規格書

## Metadata

- 功能：夢境數據分析看板（頁面二：獨立夢境數據統計看板）
- 負責人：待指派
- 狀態：草稿
- 風險等級：低

## 問題

使用者累積多篇已完成的夢境紀錄後，需要一個獨立頁面把情緒與主題趨勢視覺化，而不是只能一篇篇翻閱。

## 使用者

同一位使用者（單人，無登入）。

## 目標

- 呈現情緒趨勢折線圖、關鍵字文字雲、月曆熱力圖、情緒圓餅圖+統計摘要卡。
- 資料不足時顯示引導性空狀態，而非空白或報錯。

## 非目標

- 不含匯出圖表為圖片/PDF 的功能（可作為之後的優化項目）。
- 不含跨使用者比較或社群功能（單人專案，不適用）。
- 只讀取 `status=completed` 的日記資料，不含當天暫存中的草稿。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 情緒趨勢折線圖 | 身為使用者／我想要看到我的情緒隨時間的變化／以便了解自己近期的心理狀態 | X 軸為日期、Y 軸為情緒分類；依全部歷史資料繪製（時間範圍切換列為後續優化） |
| 關鍵字/主題文字雲 | 身為使用者／我想要看到我最常夢到的主題／以便發現潛意識關注的事 | 依出現頻率排序、字級大小反映頻率，至少顯示前 20 個關鍵字 |
| 夢境紀錄月曆熱力圖 | 身為使用者／我想要用月曆檢視哪幾天有記錄夢境／以便掌握記錄習慣 | 以顏色深淺表示當天是否有完成紀錄；可切換月份 |
| 情緒分佈圓餅圖與統計摘要卡 | 身為使用者／我想要看到整體情緒佔比與基本統計數字／以便快速掌握全貌 | 圓餅圖顯示各情緒分類佔比；摘要卡顯示總完成篇數、平均字數、記錄天數等 |
| 資料不足時的空狀態設計 | 身為使用者／我想要在還沒有足夠資料時看到引導文字而非空白圖表／以便知道該去寫日記 | 完成篇數為 0 時，四個圖表區塊皆顯示一致的引導文案與 CTA（前往寫日記） |

## 使用者旅程

```text
身為使用者
我想要切換到分析看板頁面
以便一眼看到我這段時間夢境的情緒趨勢與主題傾向
```

## 功能需求

- WHEN 使用者切換到分析看板頁面 THE SYSTEM SHALL 讀取所有 `status=completed` 的日記資料並計算四組統計。
- WHEN 已完成日記篇數為 0 THE SYSTEM SHALL 對所有圖表區塊顯示空狀態引導文案與前往日記頁的 CTA，而非渲染空圖表。
- WHEN 已完成日記篇數 ≥ 1 THE SYSTEM SHALL 正常渲染四組圖表；資料不足以形成趨勢（如僅 1 篇）時折線圖仍需優雅顯示單點而非報錯。
- WHEN 使用者在月曆熱力圖切換月份 THE SYSTEM SHALL 更新該月每日是否有紀錄的顯示，不影響其他圖表。

## 畫面

| 畫面 | 狀態 | 備註 |
|---|---|---|
| 分析看板總覽 | 有資料、空狀態(0篇)、資料極少(1-2篇的邊界顯示) | 四個圖表區塊同頁呈現 |

## 資料與 API

- 輸入：LocalStorage 中所有 `status=completed` 的日記（讀取「專案設置」Epic 定義的資料模型）。
- 輸出：純前端計算後的圖表資料，不需額外後端 API。
- 驗證：僅納入 `completed` 狀態資料。
- 錯誤：LocalStorage 資料格式異常時，該圖表區塊需能優雅降級顯示錯誤提示而非整頁白屏。

## 安全性與隱私

- 身分驗證：無。
- 權限：無。
- 敏感資料：與「專案設置」Epic 相同，全部資料僅在本機瀏覽器計算，不上傳。
- 濫用情境：不適用（純前端唯讀視覺化）。

## 驗收標準

- 四組圖表皆能正確反映 LocalStorage 資料。
- 空狀態在完成篇數為 0 時正確觸發。
- 月曆熱力圖可正確切換月份。

## 驗證計畫

- 單元測試：統計計算函式（情緒佔比、關鍵字頻率排序、月曆密度計算）。
- 整合測試：無後端串接。
- E2E：從完成一篇日記 → 切到分析看板 → 確認圖表反映該篇資料。
- 視覺：四種畫面狀態截圖。
- 手動：以多篇不同情緒/日期的測試資料人工核對圖表正確性。
