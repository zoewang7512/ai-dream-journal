# 功能規格書

## Metadata

- 功能：核心夢境日記記錄（頁面一：手繪素描日記頁面）
- 負責人：待指派
- 狀態：草稿
- 風險等級：低

## 問題

使用者需要一個仿實體手繪日記本的介面來記錄每天的夢境，且要能安全地限制 AI 生成只在「完成」當天日記後觸發一次，並保護過去紀錄不被誤改。

## 使用者

日記本身的唯一使用者（單人，無登入）。

## 目標

- 讓使用者能新增、暫存並最終「完成」當天的夢境日記。
- 完成當天日記後，以確認 dialog 提示，觸發一次性 AI 分析與圖片生成。
- 讓使用者能以翻頁方式回顧過去已完成的夢境紀錄，唯讀不可編輯。
- 允許刪除當天尚未完成的暫存日記。

## 非目標

- 不允許編輯或刪除任何已完成（含過去）的日記。
- 不在此 Epic 實作 AI 分析／圖片生成的實際邏輯（屬於「AI 夢境分析與圖像生成引擎」Epic），此 Epic 只負責觸發呼叫與顯示結果。
- 每天僅能有一篇日記，不支援同一天新增多篇（假設：符合「像日記本」的產品定位，若需求有誤請指正）。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 新增與暫存當天夢境日記 | 身為使用者／我想要在今天於日記本寫下夢境內容並隨時暫存／以便不用一次寫完 | 當天日記可輸入文字內容，未標記完成前可重複編輯與儲存；重新整理頁面後暫存內容仍在 |
| 完成當天日記並觸發 AI 生成 | 身為使用者／我想要按下完成後看到確認提示／以便清楚知道即將消耗一次 AI 額度 | 按下完成按鈕跳出確認 dialog，取消則不觸發、維持暫存狀態；確認後呼叫 AI 引擎且該篇狀態轉為已完成，之後不可再次觸發生成 |
| 翻頁瀏覽歷史夢境 | 身為使用者／我想要像翻日記本一樣往前往後看以前的紀錄／以便回顧過去的夢境 | 提供上一篇/下一篇導覽，依日期排序；沒有更多紀錄時對應方向的導覽會停用 |
| 檢視單篇夢境詳情（唯讀） | 身為使用者／我想要看到某篇過去日記的完整內容、AI 分析與生成圖片／以便回味與理解那天的夢 | 顯示原始文字、情緒/關鍵字分析結果、生成圖片；畫面上不提供編輯或刪除操作 |
| 刪除當天未完成的日記 | 身為使用者／我想要刪除還沒完成、寫錯或不想留的當天暫存日記／以便清空重寫 | 僅當天且狀態為 draft 的日記可刪除；刪除前需二次確認；已完成日記無刪除入口 |

## 使用者旅程

```text
身為使用者
我想要在睡醒後立刻寫下夢境、完成後取得 AI 生成的分析與插圖、之後還能翻回去回顧
以便累積一本可視覺化回顧的夢境日記
```

## 功能需求

- WHEN 使用者於當天日記輸入內容並儲存 THE SYSTEM SHALL 將內容以 `status=draft` 寫入該日期的紀錄。
- WHEN 使用者對非當天日期嘗試編輯或刪除 THE SYSTEM SHALL 拒絕操作，且不提供對應 UI 入口。
- WHEN 使用者按下「完成」按鈕 THE SYSTEM SHALL 先顯示確認 dialog，說明將觸發一次 AI 分析與圖片生成。
- WHEN 使用者在確認 dialog 中確認 THE SYSTEM SHALL 呼叫 AI 引擎、將該篇日記 `status` 更新為 `completed`，並在生成完成後於畫面顯示分析與圖片。
- WHEN 某篇日記 `status` 已為 `completed` THE SYSTEM SHALL 不再提供「完成」或刪除入口，且不可再次觸發 AI 生成。
- WHEN 使用者在歷史瀏覽畫面點擊上一篇/下一篇 THE SYSTEM SHALL 依日期順序切換顯示的日記，並在到達邊界時停用對應按鈕。
- WHEN 當天不存在任何日記（尚未新增）THE SYSTEM SHALL 顯示空白撰寫畫面而非錯誤。

## 畫面

| 畫面 | 狀態 | 備註 |
|---|---|---|
| 今日日記撰寫 | 預設(空白)、撰寫中(暫存)、已完成(唯讀+分析結果)、AI生成中(loading)、生成失敗 | 完成後轉為唯讀顯示分析與圖片 |
| 歷史翻頁瀏覽 | 有紀錄、無更多上一篇/下一篇(邊界)、尚無任何歷史紀錄(空狀態) | 模仿實體日記翻頁互動 |
| 完成確認 Dialog | 預設、處理中 | 提醒即將消耗 AI 額度，並告知內容將傳送給第三方 AI 服務 |

## 資料與 API

- 輸入：使用者輸入的日記文字（string，長度上限暫定 2000 字，避免 AI prompt 過長）。
- 輸出：LocalStorage 中的日記物件（沿用「專案設置」Epic 定義的資料模型）。
- 驗證：當天日期以使用者本機時區判斷；空白內容不可標記完成。
- 錯誤：AI 生成失敗時，日記狀態需回退為可重試（不可卡在「生成中」），並顯示錯誤訊息（實際重試邏輯屬 AI 引擎 Epic）。

## 安全性與隱私

- 身分驗證：無。
- 權限：無。
- 敏感資料：日記內容為個人隱私/心理狀態相關資料，僅存本機 LocalStorage；確認 dialog 需讓使用者知情「內容將傳送給第三方 AI 服務」。
- 濫用情境：防止對同一篇日記重複觸發 AI 生成而超額耗用免費額度（已用一次性狀態鎖定 + 確認 dialog 因應）。

## 驗收標準

- 使用者能完整走完「新增暫存 → 完成觸發 AI → 翻頁回顧」的旅程。
- 過去日記在任何情況下都無法被編輯或刪除。
- 已完成日記無法重複觸發 AI 生成。

## 驗證計畫

- 單元測試：日記狀態機（draft→completed）轉換邏輯、當天判斷、刪除限制。
- 整合測試：完成日記 → 呼叫 AI 引擎（mock）→ 更新狀態的完整流程。
- E2E：新增 → 完成 → 翻頁回顧的完整使用者旅程。
- 視覺：三種畫面狀態截圖比對 `design-system.md` 版型。
- 手動：確認 dialog 的取消/確認分支皆手動走一次。
