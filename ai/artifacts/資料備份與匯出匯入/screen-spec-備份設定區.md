# 畫面規格

## Metadata

- 功能：資料備份與匯出/匯入
- 畫面：備份設定區
- 狀態：mockup 已核准（變體 C · Nav 齒輪圖示開啟 Modal，見 `mockup-decision-備份設定區.md`）

## 目的

讓使用者找到「匯出全部資料」「匯入備份資料」這兩個操作的入口。這個畫面本身不做資料視覺化，只是備份/還原這個次要維運功能的容器；主要任務仍是頁面一（寫日記）與頁面二（數據看板）。TASK-027（本卡涵蓋，匯出）與 TASK-028（匯入，後續任務卡）共用同一個畫面容器，只是分兩張任務卡實作。

## 版面配置

- 主要區域：Nav 列右側齒輪圖示按鈕開啟的 Modal，內含匯出按鈕（本卡）＋匯入按鈕與確認流程（TASK-028，本卡先保留版位）。
- 次要區域：Modal 內簡短說明文字（備份檔用途、匯入會整批覆蓋的提醒）。
- 導覽：不新增路由；`Nav` 列右側新增一個齒輪圖示按鈕（`aria-label="備份設定"`），點擊開啟 `Modal`。兩個既有頁面（日記／看板）完全不受影響。
- 動作：點擊齒輪圖示 → 開啟 Modal → 點擊「匯出備份」→ 觸發瀏覽器下載 JSON 檔 → 可關閉 Modal。

## 狀態

| 狀態 | 必要行為 | 空狀態／錯誤文案 | 驗證方式 |
|---|---|---|---|
| 預設 | 顯示匯出按鈕與說明文字 | 不適用 | 螢幕截圖 |
| 載入中 | 匯出是同步操作（LocalStorage 讀取＋觸發下載），不需要載入態；若瀏覽器下載 API 有延遲則按鈕短暫停用 | 不適用 | 螢幕截圖 |
| 空狀態 | 沒有任何已完成日記時，匯出仍可執行（產出只有空陣列 `dreams: []` 的合法備份檔），不阻擋 | 不特別提示（合法情境，不算錯誤） | 螢幕截圖 |
| 錯誤 | LocalStorage 讀取或瀏覽器下載觸發失敗時顯示錯誤提示（沿用既有 Toast 元件） | 「匯出失敗，請稍後再試。」 | 螢幕截圖 |
| 停用 | 不適用（本卡沒有需要停用按鈕的情境） | 不適用 | 不適用 |
| 權限不足 | 不適用（單人專案、無登入） | 不適用 | 不適用 |
| 行動裝置版 | 按鈕與說明文字單欄堆疊，不需要側邊欄或多欄版面 | 同預設 | 螢幕截圖 |

## 互動

| 動作 | 觸發條件 | 結果 | 失敗情境 |
|---|---|---|---|
| 點擊「匯出備份」 | 使用者點擊按鈕 | 產生 `{ version, exportedAt, dreams: [...] }` JSON，觸發瀏覽器下載，檔名 `dreamweaver-backup-YYYY-MM-DD.json` | LocalStorage 讀取異常或瀏覽器阻擋下載時顯示錯誤 Toast，不影響現有資料 |

## 設計系統對照

- 用到的既有 design token：`--font-family-hand`、`--font-family-serif`、`--font-size-*`、`--space-*`、`--radius-*`、`--shadow-card`、`--color-*`（依選定變體實際使用項目為準）。
- 用到的既有元件：`Button`（primary variant，匯出動作）、`Card`（若變體需要容器）、`Toast`（錯誤提示）、`Nav`（若選擇新增導覽入口的變體）。
- 本畫面新做的元件：無（純粹用既有元件與版面組合達成，不需要新元件）。

## 視覺驗收標準

- 文字在手機版與桌面版都不會被截斷。
- 主要動作（匯出備份）清楚明確，不會被其他次要資訊搶走視覺重量。
- 錯誤狀態明確呈現（Toast）。
- 色彩、字體、間距、圓角、陰影一律取自 `design-system.md` 的 design token，沒有硬寫的一次性數值。
- 重複使用元件庫 inventory 裡的既有元件；本畫面未新增任何元件。
