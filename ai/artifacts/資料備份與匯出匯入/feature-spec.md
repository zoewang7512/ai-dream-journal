# 功能規格書

## Metadata

- 功能：資料備份與匯出/匯入
- 負責人：待指派
- 狀態：草稿
- 風險等級：低（涉及資料覆蓋操作，需注意資料完整性）

## 問題

資料僅存於單一瀏覽器的 LocalStorage，清除瀏覽器資料、換裝置或換瀏覽器都會造成夢境紀錄永久遺失，需要備份與還原機制。

## 使用者

同一位使用者（單人，無登入）。

## 目標

- 讓使用者能將全部資料匯出成單一 JSON 檔案下載。
- 讓使用者能匯入先前匯出的 JSON 檔案，寫回 LocalStorage。
- 匯入/匯出失敗時給予清楚錯誤提示。

## 非目標

- 不支援雲端自動同步/自動備份（單純手動匯出/匯入）。
- 不支援部分匯入（例如只匯入某幾篇），一律整批匯入/匯出。
- 匯入衝突策略採「整批覆蓋」而非逐筆合併：匯入前明確提示「將覆蓋目前所有本機資料」，不實作逐筆合併演算法。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| 匯出全部資料為 JSON | 身為使用者／我想要把所有夢境紀錄下載成一個檔案／以便保存備份或搬到別的裝置 | 點擊匯出後下載一個含版本號與全部日記資料的 JSON 檔，檔名含日期 |
| 匯入 JSON 恢復資料 | 身為使用者／我想要上傳備份檔把資料復原／以便換瀏覽器或不小心清除資料後還能找回 | 選擇檔案後顯示「將覆蓋目前資料」確認提示，確認後解析並整批覆蓋 LocalStorage，成功後畫面即時反映新資料 |
| 匯入/匯出失敗的錯誤提示 | 身為使用者／我想要在檔案有問題時得到清楚說明／以便知道問題出在哪 | 檔案非 JSON、缺少版本欄位、版本不支援、內容格式不符時，顯示對應錯誤訊息且不寫入任何資料（全有或全無） |

## 使用者旅程

```text
身為使用者
我想要在換裝置前匯出備份、在新裝置上匯入
以便不遺失累積的夢境紀錄
```

## 功能需求

- WHEN 使用者點擊「匯出備份」THE SYSTEM SHALL 產生含 `{ version, exportedAt, dreams: [...] }` 結構的 JSON 並觸發瀏覽器下載，檔名格式如 `dreamweaver-backup-YYYY-MM-DD.json`。
- WHEN 使用者選擇檔案匯入 THE SYSTEM SHALL 先顯示「將覆蓋目前所有資料」確認提示，取消則不執行任何寫入。
- WHEN 使用者確認匯入且檔案格式合法 THE SYSTEM SHALL 整批覆蓋 LocalStorage 中的日記資料，並更新畫面顯示結果。
- WHEN 匯入檔案格式不合法（非 JSON、缺欄位、版本不相容）THE SYSTEM SHALL 顯示對應錯誤訊息且不修改任何現有 LocalStorage 資料。

## 畫面

| 畫面 | 狀態 | 備註 |
|---|---|---|
| 匯出/匯入設定區 | 預設、匯入確認中、匯入成功、匯入失敗(含錯誤原因) | 可放在設定區或日記頁的次要入口 |

## 資料與 API

- 輸入：使用者上傳的 JSON 檔案（File API 讀取）。
- 輸出：下載的 JSON 檔／覆蓋後的 LocalStorage。
- 驗證：JSON parse 成功、`version` 欄位存在且支援、`dreams` 為陣列且每筆符合「專案設置」Epic 的資料模型欄位。
- 錯誤：`parse 失敗` / `欄位缺失` / `版本不支援` 三類，各自對應訊息。

## 安全性與隱私

- 身分驗證：無。
- 權限：無。
- 敏感資料：備份檔包含完整夢境內容，使用者需自行妥善保管下載的檔案（UI 文案需提醒）。
- 濫用情境：匯入內容需經過驗證與適當跳脫，避免惡意構造的匯入檔案在任何以 HTML 呈現日記內容之處造成 XSS。

## 驗收標準

- 匯出檔可被同一機制成功匯入還原。
- 格式錯誤的檔案不會破壞現有資料（原子性）。

## 驗證計畫

- 單元測試：匯出序列化、匯入驗證與反序列化函式（含各種壞資料的邊界測試）。
- 整合測試：匯出 → 清空 → 匯入的往返（round-trip）測試。
- E2E：使用者操作匯出下載 → 匯入同檔案 → 資料一致。
- 視覺：匯入確認/成功/失敗三種狀態截圖。
- 手動：用壞掉的 JSON 檔案人工測試錯誤訊息是否清楚。
